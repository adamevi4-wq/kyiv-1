# Kyiv-1 site work — metaprompt

Це робочий промпт для всіх змін сайту Kyiv-1 (дашборд для дістрикт-менеджера
Адама) і його Telegram-бота. Він тримає разом процес, обмеження й звички, які
вже перевірено на практиці. Він живий: у кінці кожної роботи оновлюй розділ
"Журнал і ідеї" внизу.

Спершу читай за потреби суміжні skill-и, а не перевідкривай їхній зміст:
`site-and-document-craft` (загальний процес), `visual-design-principles`
(дизайн), `jysk-dashboard-report` (візуальна мова JYSK), `dataviz` (графіки),
`kyiv1-kpi-update` (нові періоди звітів), `kyiv1-deliveries-update`
(доставки), `kyiv1-daily-check` (бот і прив'язки), `kyiv1-bot-copywriter` і
`kyiv1-ask-bot-persona` (тексти й персона бота).

## 1. Перед будь-чим: з чим маєш справу

- Сайт: https://kyiv1-dashboard.com/ (Cloudflare Pages, деплой з `main`).
  Репозиторій: `adamevi4-wq/kyiv-1` (стара назва `store-tracker` теж працює
  через перенаправлення).
- Ця сесія **не має доступу** до живого сайту, до Firestore для запису і до
  живого рендеру. Доступні лише GitHub, npm і Anthropic. Не обіцяй Адаму
  "перевірю на сайті" — перевіряй локально, а живе підтвердження проси в
  нього (скріншот або "працює").
- Запис у Firestore з цієї сесії неможливий. Дані, які треба вставити
  вручну, давай як готовий JSON або чіткий список, а не як "зроблю сам".
- Правила Firestore (`firestore.rules`) CI **не деплоїть**. Після зміни їх
  треба опублікувати вручну (Firebase console або
  `firebase deploy --only firestore:rules`). Завжди нагадуй про це в PR і в
  повідомленні Адаму.
- Адам — дістрикт-менеджер, не розробник. Пояснюй результат простою
  українською: що змінилось, де це побачити, що йому зробити. Не вивалюй
  логи команд.

## 2. Процес зміни

1. **Оріентація.** `git fetch origin main`, `git log origin/main --oneline -10`,
   перевір `git status`. Не продовжуй гілку, яку вже змерджено: завжди
   створюй нову від `origin/main`.
2. **Гілка.** `git checkout -b claude/<коротка-назва> origin/main`.
3. **Розвідка перед кодом.** Знайди, чи вже є компонент, що робить це
   (`gaugeHtml`, `kpiBarRow`, `.attn-row`, `.tg-bar-row`, `heroBannerHtml`,
   `.card`, `.empty-state`, `.tab-btn`). Перевикористовуй його. Новий виджет —
   лише коли жодний не підходить.
4. **Правка.** Мінімальна. Не чіпай сусідній код "заодно". Коментарі — лише
   коли причина неочевидна (обмеження, обхідний шлях). Ніяких планувальних
   чи історичних коментарів.
5. **Перевірка перед комітом** (обов'язково):
   - `node --check` на витягнутому `<script type="module">` з `index.html`
     і на `telegram-bot/worker.js`, якщо він змінювався.
   - `npm test` (headless Playwright, `tests/smoke.mjs`). Smoke-тест **не
     покриває** розгорнуті категорії (Мобіліті, 7-й код, Комплексні продажі з
     `categories`) і не покриває bulk-імпорт вакансій. Для таких змін пиши
     окремий scratch-скрипт.
   - Scratch-скрипт у корені: `_<назва>.mjs`, з `tests/fbstub/` замість
     Firebase, з `window.__SEED__` для даних, з логіном `DM-Kyiv1`. Знімки
     роби в scratchpad, не в репозиторії. Перевіряй **десктоп (1400px) і
     мобільний (390px)**, а для візуальних змін ще й темну тему.
   - Перед комітом видали всі `_*.mjs` з репозиторію і тимчасові файли в `/tmp`.
6. **Коміт.** Повідомлення українською, про "чому". Трейлери:
   `Co-Authored-By: Claude <noreply@anthropic.com>` і
   `Claude-Session: https://claude.ai/code/session_012XWM6jQmRnDjPvNFPovxpR`.
   **Жодної назви моделі** в комітах, назвах чи описах PR.
7. **Push.** `git push -u origin <гілка>`. Якщо мережа падає — повтори з
   затримкою 2, 4, 8, 16 с.
8. **PR і мердж.** Відкривай PR, мерджі squash **лише коли Адам просить**
   ("змерджи", "зроби PR"). Інакше коміт і push — і запропонуй PR. Для PR
   бери шаблон з `.github/pull_request_template.md`, якщо він є. Опис
   закінчуй рядком `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
   і посиланням на сесію.
9. **Після PR.** Підпишись на активність (`subscribe_pr_activity`), постав
   одну перевірку CI через `send_later` (5 хв), на зеленому `smoke` і
   `Cloudflare Pages` мерджі, відпишись і скасуй перевірку (`delete_trigger`).
   `Workers Builds: kyiv1-telegram-bot` червоний майже на всіх PR через legacy
   чек: він не блокує, але для PR, що міняє `telegram-bot/`, перевір, що
   деплой через `deploy-telegram-bot.yml` пройшов.
10. **Звіт Адаму.** Коротко, українською: що змінилось, де подивитись, що йому
    треба зробити (правила Firestore, вставити JSON, очистити кеш).

## 3. Дані: що куди вносити

- **KPI-звіти** ("Звіти та показники": Мобіліті, 7-й код, Комплексні,
  Click & Collect, Розпродаж): через віджет "➕ Імпортувати новий період
  (JSON, адмін)". Новий період додається. Та сама `id` запитує підтвердження
  і замінює запис. Історію не переписуй без прямого прохання.
- **Вакансії:** через "➕ Імпортувати вакансії списком (JSON, адмін)".
  Імпорт **лише додає**. Видалення окремої вакансії — поштучно через ×.
  Масового видалення живих даних не роби й не пропонуй.
- **Доставки:** `DELIVERIES_BY_MONTH` у `index.html`, це код, тож іде через PR.
- **Прив'язки бота:** `kyiv1/telegram-unlinked-<chatId>` (щоденний снапшот
  після 08:00). Читається лише адміном, після опублікування правил.
- **Персональні дані** (імена, Telegram id, зарплатні/кадрові поля): не
  виводь у чат більше, ніж треба, і не клади в репозиторій.
- Якщо потрібних даних немає — скажи це. Не вигадуй цифри, імена, REF-коди.

## 4. Стиль і тон

- Українська скрізь у видимому тексті.
- Жодних осудливих превосходних для людей і магазинів: "найгірший",
  "найслабший" заборонено. Використовуй "потребують уваги", "фокус на".
- Візуально: токени з `style.css` (`--navy`, `--red`, `--green`,
  `--font-sans`, `--font-mono`, `--radius`, `--tab-accent`), а не літерали.
  Темна тема має працювати. Перевіряй обидві.
- Великі візуальні зміни спершу показуй як макет (Artifact), а вже потім
  переносити на сайт. Адам так зробив зі стилем Мобіліті.
- Не додавай функцій "про запас". Видалення фіч, які Адам прибрав, назад не
  повертай без прямого прохання.

## 5. Відомі пастки

- **Кеш браузера.** Після мерджу більшість "не змінилось" — це старий CSS/JS.
  Перша порада: жорстке оновлення (Ctrl+Shift+R) або інкогніто.
- **Градієнт при однаковому значенні.** `kpiGradientColor` повертає `null`,
  коли `lo === hi`. Для категорій є `kpiCategoryChipColor` з фолбеком 0–100.
- **Flex-ширини.** `flex: N` (grow) роздуває колонку на широких екранах.
  Для фіксованих колонок став `flex: 0 1 <px>` або `width`.
- **CSS Grid з `1fr`** розтягує маленькі чіпи. Для них кращий `flex-wrap`.
- **Firestore-сервісний акаунт** обходить правила. Тому бот може писати
  там, куди клієнту заборонено. Не плутай ці дві площини.
