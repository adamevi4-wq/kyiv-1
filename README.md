# Трекер показників дістрікту

Веб-застосунок для щомісячного відстеження показників по магазинах
дістрікту. Дані синхронізуються **в реальному часі** між усіма, хто
відкрив посилання — з телефону, ноутбука, будь-де, — через безкоштовний
Firebase Firestore. Хостинг — безкоштовний GitHub Pages (розгортається
автоматично при кожному push у `main`).

Кожна зміна (число в клітинці, нова назва магазину, новий показник)
з'являється в браузерах усіх інших відкритих вкладок за секунду-дві, без
оновлення сторінки. Застосунок також працює офлайн (в літаку, у метро) —
зміни зберігаються локально і синхронізуються, щойно з'явиться інтернет.

## 1. Створіть безкоштовний Firebase-проєкт (5 хвилин, без картки)

1. Відкрийте <https://console.firebase.google.com>, увійдіть Google-акаунтом.
2. **Add project** → введіть назву (напр. `district-tracker`) → Continue → можна
   вимкнути Google Analytics → **Create project**.
3. У лівому меню: **Build → Firestore Database → Create database**.
   - Оберіть регіон (найближчий до вас) — потім не можна змінити.
   - Оберіть **Start in production mode** (правила безпеки вже лежать у
     `firestore.rules` цього репозиторію — застосуйте їх, як описано в
     кроці 4).
4. Встановіть правила Firestore: у вкладці **Rules** вставте вміст файлу
   [`firestore.rules`](./firestore.rules) з цього репозиторію та натисніть
   **Publish**. (Це відкриті правила — доступ контролюється посиланням
   із кодом кімнати, детальніше в коментарі у файлі.)
5. Поверніться на **Project overview** → значок `</>` (**Add app → Web**) →
   дайте назву → **Register app**. Firebase покаже об'єкт `firebaseConfig`
   із ключами — скопіюйте його.

## 2. Підключіть конфіг у коді

Відкрийте [`src/firebaseConfig.js`](./src/firebaseConfig.js) і вставте
значення, які скопіювали на попередньому кроці, замість `YOUR_...`.

Це не секретні дані — такий конфіг завжди публічний у Firebase-застосунках
для браузера (безпека забезпечується правилами Firestore, а не
приховуванням цього файлу), тому його можна спокійно закомітити в git.

## 3. Локальний запуск (перевірити, що працює)

```bash
npm install
npm run dev
```

Відкриється адреса на кшталт `http://localhost:5173`. Відкрийте її у двох
вкладках і введіть число в одну — воно з'явиться в іншій майже миттєво.

## 4. Безкоштовний хостинг: GitHub Pages (автоматично)

Репозиторій вже містить workflow
[`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml), який при
кожному push у `main` збирає застосунок і публікує його на GitHub Pages.

Потрібно один раз увімкнути це в налаштуваннях репозиторію:

1. На GitHub: **Settings → Pages → Build and deployment → Source** →
   оберіть **GitHub Actions**.
2. Змерджіть цю гілку в `main` (або запуште зміни в `main`) — запуститься
   workflow **Actions** → за хвилину-дві сайт буде доступний за адресою
   `https://<ваш-github-логін>.github.io/store-tracker/`.

Кожен наступний `git push` у `main` автоматично оновлює сайт — окремий
деплой руками не потрібен.

### Альтернативи (теж повністю безкоштовні)

- **Firebase Hosting** — логічно поєднати з Firestore з того ж проєкту:
  ```bash
  npm run build
  npx firebase-tools login
  npx firebase-tools deploy --only hosting,firestore:rules
  ```
  (перший запуск попросить обрати проєкт, створений у кроці 1; конфігурація
  вже лежить у `firebase.json`).
- **Netlify** / **Vercel** — під'єднайте GitHub-репозиторій у їхньому
  дашборді, build command `npm run build`, output directory `dist`.
  Обидва мають безкоштовний план без картки.

## Як це працює

- **Дані**: один документ Firestore на "кімнату" (`districts/{room}`),
  що містить список магазинів, список показників і всі внесені значення
  по місяцях. Слухач `onSnapshot` тримає його синхронізованим у реальному
  часі з усіма відкритими вкладками/пристроями.
- **Кімнати**: посилання виду `?room=якийсь-код` відкриває окремий,
  ізольований трекер — зручно, якщо потрібно кілька незалежних дістріктів.
  Без параметра використовується кімната `default`. Кнопка «🔗 Поділитися»
  вгорі показує та копіює посилання для колег.
- **Офлайн-режим**: Firestore кешує дані локально в браузері (IndexedDB) і
  автоматично довантажує/відправляє зміни при появі мережі — статус видно
  у бейджі поруч із заголовком («Онлайн · синхронізовано» / «Офлайн…»).
- **Безкоштовні ліміти**: Firestore Spark-план дає 1 ГБ сховища й 50 000
  читань / 20 000 записів на день — для команди з кількох людей і
  десятків магазинів цього вистачить із великим запасом, картка не
  потрібна.

## Структура проєкту

```
index.html              вхідна HTML-сторінка (Tailwind CDN для стилів)
src/main.jsx             точка входу React
src/StoreTracker.jsx      сам застосунок (UI + логіка Firestore)
src/firebase.js           ініціалізація Firebase/Firestore + офлайн-кеш
src/firebaseConfig.js     ← сюди вставляєте свій Firebase config
firestore.rules           правила безпеки Firestore
firebase.json             конфіг для `firebase deploy` (Hosting/Firestore)
.github/workflows/deploy.yml  автодеплой на GitHub Pages
```
