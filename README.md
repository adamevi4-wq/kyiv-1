# Dashboard Kyiv 1

Веб-панель управління дістриктом Kyiv-1: ставки й укомплектованість
магазинів, вакансії (з відстеженням time-to-fill), зони відповідальності
амбасадорів. Один статичний HTML-файл (`index.html`) — без збірки, без
Node/npm на сервері.

Дані синхронізуються **в реальному часі** через безкоштовний Firebase
Firestore: зміна, внесена одним керуючим, з'являється в браузерах усіх
інших користувачів за секунду, без оновлення сторінки. Хостинг —
безкоштовний GitHub Pages, деплой автоматичний при кожному push у `main`.

🔗 **Сайт:** https://adamevi4-wq.github.io/kyiv-1/

## Вхід

- **Керуючий** — обирає свій магазин зі списку, пароль за замовчуванням =
  код магазину (напр. `J104`). Може редагувати дані лише свого магазину;
  дані інших магазинів бачить, але не змінює.
- **District Manager** — пароль за замовчуванням `DM-Kyiv1`. Повний доступ,
  плюс адмін-панель для перегляду/зміни паролів усіх керуючих.

Кожен користувач може змінити свій пароль кнопкою **«Пароль»** у шапці
після входу — зробіть це одразу після першого запуску.

⚠️ **Важливо про безпеку:** цей "логін" — зручність для організації
роботи, а не справжній захист даних. Правила Firestore (`firestore.rules`)
відкриті для будь-кого, хто знає конфігурацію проєкту (вона публічна,
лежить у коді сторінки) — тобто технічно охочий може прочитати чи змінити
дані в обхід екрана входу. Для команди з кількох довірених людей це
прийнятний компроміс (аналог "посилання = пароль" у Google Docs); якщо
потрібен реальний захист — треба вмикати Firebase Authentication (див.
коментар у `firestore.rules`).

## Вкладки

1. **Магазини та ставки** — норма/сезонна норма/факт по ставках і людях
   на кожен магазин, ЦПХ, ризиковані працівники, працівники з
   інвалідністю, коментар до магазину.
2. **Вакансії** — список вакансій дістрикту з датою відкриття/закриття,
   статусом, ціллю time-to-fill (30 днів), простроченими вакансіями,
   відповідальним, пріоритетом.
3. **Відповідальність** — зони відповідальності амбасадорів по категоріях
   (навчання, sales attitude, операції, люди, матеріально-технічна база) з
   прогрес-баром і коментарями.
4. **Активність** (тільки для District Manager) — скільки разів і коли
   кожен керуючий заходив на сайт: усього входів, за 7/30 днів, дата
   останнього входу, статус («регулярно», «мовчить >7 днів», «ще не
   заходив»), плюс стрічка останніх входів усіх користувачів.

## Локальний перегляд

Просто відкрийте `index.html` у браузері — або підніміть будь-який
статичний сервер, напр.:

```bash
npx serve .
```

## Хостинг (уже налаштовано, автоматично)

Workflow [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml)
публікує `index.html` на GitHub Pages при кожному push у `main` — нічого
збирати не потрібно. Щоб увімкнути: **Settings → Pages → Build and
deployment → Source → GitHub Actions** (одноразово).

### Альтернатива: Firebase Hosting

```bash
npx firebase-tools login
npx firebase-tools deploy --only hosting,firestore:rules
```

## Firebase-проєкт

Використовується той самий безкоштовний проєкт (`district-tracker-ef4c6`,
Spark-план — 0 грн), що й для попередньої версії трекера; конфіг уже
вписаний у `index.html`. Дані зберігаються в колекції `kyiv1` — по одному
документу на кожен блок даних (`users`, `zones`, `staffing-stores`,
`vacancies`, `login-log`, `admin-password`), кожен з полем `value`
(JSON-рядок).

Щоб перенести застосунок на власний Firebase-проєкт: створіть новий
проєкт на https://console.firebase.google.com, увімкніть Firestore,
опублікуйте правила з `firestore.rules`, зареєструйте веб-застосунок і
вставте новий `firebaseConfig` замість поточного в `index.html`
(шукайте `const firebaseConfig = {`).

## Як це працює технічно

- **Реальний час**: `onSnapshot` слухає 5 документів Firestore і
  застосовує зміни миттєво — але не тоді, коли користувач саме щось вводить
  (курсор в полі вводу, відкрита модалка коментарів/пароля, відкрита форма
  додавання вакансії), щоб не збивати активне редагування.
- **Автозбереження**: зміни в полях застосовуються по події `change`
  (втрата фокусу / Enter), з невеликим дебаунсом (250 мс) для частих
  полів — і одразу йдуть у Firestore.
- **Безкоштовні ліміти**: Firestore Spark-план — 1 ГБ сховища, 50 000
  читань і 20 000 записів на день; для команди з кількох людей і 10
  магазинів цього вистачає з великим запасом.
