# Telegram-бот Kyiv-1

Бот для групового чату дістрикту: адміністрування (модерація, попередження,
антифлуд, welcome-повідомлення), статистика активності учасників, звіти по
вакансіях/активності керуючих з дашборду (`../index.html`) та запрограмовані
нагадування й щоденний дайджест.

Працює через Telegram webhook на **Cloudflare Workers** (безкоштовно, без
власного сервера) і зберігає свій стан у тому самому безкоштовному Firebase-
проєкті (`district-tracker-ef4c6`), що й дашборд — колекція `telegram-bot`.
Cron-тригер Cloudflare (раз на 5 хв) розсилає нагадування та дайджест.

## 1. Створити бота в Telegram

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot`, дайте назву.
2. Отримаєте **токен** виду `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — знадобиться нижче.
3. (Бажано) `/setprivacy` → `Disable` — щоб бот бачив усі повідомлення в
   групі, а не лише команди, адресовані йому (потрібно для антифлуду й
   статистики).

## 2. Розгорнути Worker на Cloudflare

Потрібен безкоштовний акаунт на [cloudflare.com](https://dash.cloudflare.com/sign-up).

```bash
cd telegram-bot
npm install -g wrangler   # якщо ще не встановлено
wrangler login

wrangler secret put BOT_TOKEN
# вставте токен від BotFather

wrangler secret put WEBHOOK_SECRET
# вставте будь-який випадковий рядок (напр. відкрийте
# https://www.uuidgenerator.net і скопіюйте один UUID) — це пароль,
# яким Telegram підписуватиме запити до вашого Worker

wrangler deploy
```

Після `wrangler deploy` у терміналі з'явиться URL виду
`https://kyiv1-telegram-bot.<ваш-субдомен>.workers.dev` — він знадобиться
на наступному кроці.

### Автодеплой при кожній зміні коду (одноразове налаштування)

Це потрібно зробити лише один раз, руками, в самому Cloudflare — жоден
асистент не може увійти у ваш акаунт замість вас. Після цього кроку
`telegram-bot/worker.js` деплоїться сам при кожному push у `main`
(workflow [`deploy-telegram-bot.yml`](../.github/workflows/deploy-telegram-bot.yml)),
точно як `index.html` вже деплоїться на GitHub Pages — команда
`wrangler deploy` вище більше не знадобиться для звичайних оновлень коду
бота.

1. [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)
   → **Create Token** → шаблон **"Edit Cloudflare Workers"** → Create
   Token. Скопіюйте токен (показується один раз).
2. У Cloudflare Dashboard → **Workers & Pages** — у правій колонці є
   **Account ID**, скопіюйте і його.
3. У GitHub-репозиторії: **Settings → Secrets and variables → Actions →
   New repository secret** — додайте два секрети:
   - `CLOUDFLARE_API_TOKEN` — токен з кроку 1
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID з кроку 2

Після цього наступний push, що зачіпає `telegram-bot/`, задеплоїть Worker
автоматично; перший запуск можна ініціювати вручну — вкладка **Actions**
цього репозиторію → **Deploy Telegram bot (Cloudflare Worker)** → **Run
workflow**.

## 3. Підключити webhook

Один раз відкрийте в браузері (підставте свій `BOT_TOKEN`, `WORKER_URL` і
`WEBHOOK_SECRET`):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WORKER_URL>&secret_token=<WEBHOOK_SECRET>
```

Успішна відповідь: `{"ok":true,"result":true,...}`.

### Реакції (для щотижневого дайджесту й відстеження ознайомлень, опційно)

Без цього кроку все інше в боті працює нормально — не пропускайте
попередній крок, а цей робіть лише якщо хочете, щоб:
- щотижневий дайджест показував, чиє привітання зібрало найбільше
  реакцій 👍❤️🔥 (потрібен тип `message_reaction_count`);
- і/або запрацювали «Тригери на реакції» (`/trackack` — ознайомлення з
  інструкціями через реакції; потрібен тип `message_reaction`);
- і/або запрацювали кнопки `/menu` (потрібен тип `callback_query` —
  без нього кнопки будуть видимі, але натискання на них нічого не
  робитиме, крім вічного «крутиться» індикатора завантаження).

За замовчуванням Telegram не надсилає боту жодних даних про реакції чи
натискання кнопок — треба один раз переустановити webhook, вказавши явно,
які типи оновлень бот хоче отримувати (це замінює список типів повністю,
тож перелічіть усі, а не лише нові).

**Найпростіше** — просто напишіть у чаті команду (адміни чату):

```
/registerwebhook
```

Бот сам викличе Telegram API з правильним `URL` (бере його прямо із цього
запиту — не треба нікуди підставляти субдомен вручну) і повним списком
`allowed_updates`. У відповідь напише ✅ або опише, що саме пішло не так.

Альтернатива (вручну, якщо `/registerwebhook` з якоїсь причини недоступний
— наприклад бот узагалі не відповідає): відкрийте в браузері (підставте
свій `BOT_TOKEN`, `WORKER_URL` і `WEBHOOK_SECRET`):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WORKER_URL>&secret_token=<WEBHOOK_SECRET>&allowed_updates=["message","poll","poll_answer","message_reaction","message_reaction_count","callback_query"]
```

Успішна відповідь: `{"ok":true,"result":true,...}`. Якщо цей крок
пропустити — весь інший функціонал працює як завжди, просто рядок
"найпопулярніше привітання тижня" в щотижневому дайджесті не з'явиться,
реакції на повідомлення під `/trackack` не зараховуватимуться (сама
команда й `/ackstatus`/`/acklist` працюють одразу, незалежно від цього
кроку — просто список «ознайомились» лишиться порожнім), а кнопки в
`/menu` не відповідатимуть на натискання.

### AI-квізи за презентаціями (опційно)

Без цього кроку команда `/setquiztopic` і завантаження `.pptx` у прив'язану
тему все одно працюють — квіз просто складається механічно («до якого
слайду належить цей текст», без розуміння змісту). Щоб бот замість цього
писав Claude і отримував квіз зі справжніми питаннями на розуміння змісту
презентації (з урахуванням і тексту, і фото на слайдах):

```bash
wrangler secret put ANTHROPIC_API_KEY
# вставте ключ з https://console.anthropic.com/settings/keys
```

Наступне завантаження презентації в тему квізів автоматично піде через
Claude — коду міняти не треба. Коштує невелику суму за кожну завантажену
презентацію (один запит, не за кожне питання) — і жодних витрат, поки цей
секрет не додано.

### Звернення до бота (опційно)

Той самий секрет (`ANTHROPIC_API_KEY`) вмикає живого AI-співрозмовника:
досить написати слово «бот» будь-де в повідомленні (у будь-якому регістрі
— бот/БОТ/Бот, навіть просто в контексті фрази) — або згадати через `@`,
або відповісти на будь-яке повідомлення бота. Персона — дружній, з легким
гумором співрозмовник (а не формальний «бот-помічник»): читає настрій, на
реальне питання відповідає конкретно по суті, на привітання чи скаргу на
втому — щирою короткою мотивацією без пафосу.

**Розуміє контекст, а не лише буквальний текст:** коротка репліка типу
«ясно», «ну таке», «ага», «дякую» не отримує шаблонної відповіді — бот
визначає, що вона означає саме в поточному діалозі. На сарказм,
неформальний стиль, помилки чи суржик реагує по суті, а не буквально. На
агресію чи токсичність не конфліктує — залишається спокійним. Якщо сенс
неоднозначний — ставить одне коротке уточнення замість вигаданої
відповіді.

**Може промовчати, коли відповідь не потрібна:** якщо повідомлення
насправді не адресоване боту, це продовження чужої розмови, флуд, спам,
провокація без реального запиту, чи проста репліка на кшталт «дякую»/👍 у
відповідь на власне повідомлення бота — бот свідомо нічого не надсилає
(навіть заготовленої фрази). Це рішення приймає лише AI-шлях — якщо ключа
немає, бот завжди відповідає (заготовленим текстом), бо без AI нема кому
судити, чи варто мовчати.

Розуміє й фото/документи (.pdf, .txt та подібні текстові файли) — досить
прикріпити з підписом «бот, що тут?»: чек — коментує суму/дату/підозрілі
позиції; стенд чи товар — оцінює як рітейлер; скріншот з помилкою чи
інтерфейсом — пояснює, що це означає й що робити, а не просто переказує
текст. Короткий підпис («ось», «дивись», «шо це?») розшифровує через сам
вміст фото. Нечітке фото — просить чіткіше замість вигадування деталей;
на емоційне звернення з фото — спершу коротко визнає емоцію, потім суть.
**Аналіз фото працює навіть без `ANTHROPIC_API_KEY`** — якщо Claude
недоступний, те саме фото (чек, стенд, скріншот) іде до безкоштовної
Cloudflare-моделі (той самий рівень, що й `askWorkersAI` — формат
запиту з зображенням підтверджено зі схеми моделі, той самий OpenAI-
подібний `image_url` блок). PDF/документи лишаються лише через Claude
(платно) — для них немає підтвердженого безкоштовного формату.
Голосові/відео поки що чесно (і з гумором) визнає, що не вміє їх
«слухати»/«дивитись» — Claude не приймає аудіо/відео на вхід, а окремого
сервісу розпізнавання мовлення (Whisper тощо) тут не підключено: це б
означало ще один платний API — скажи, якщо хочеш його додати, і я
підключу.
Знає, **хто саме звертається** (реальне ім'я з профілю Telegram), і якщо
це відповідь на конкретне повідомлення — бачить його текст, навіть якщо
відповідають на власну попередню репліку бота (яка інакше ніде не
зберігається — короткий контекст чату нижче фіксує лише повідомлення
людей, не бота). Враховує кілька останніх реплік чату як контекст (без
окремого запису у Firestore — довантажується до вже наявного) — і,
окремо, **реальний знімок активності по темах форуму**, прив'язаних у
цьому чаті: скільки
магазинів уже відзвітували сьогодні (вечірні звіти й фотозвіти окремо),
хто ще ні, поточні стріки, топ активності за сьогодні, стан щомісячного
чекліста. Тобто на «як у нас справи сьогодні» бот відповідає реальними
цифрами з бази, а не загальними словами — і аналізує «паралельно»
одразу декілька тем/гілок чату, не лише ту, де прозвучало запитання.
Показуються лише ті розділи, які в цьому чаті взагалі налаштовані — якщо
`/setreportstopic` не викликали, рядка про звіти просто не буде. Разом
із цим бот отримує й **довідку про самі магазини** (код, назва,
керуючий — те саме, що вже показує дашборд) — щоб на «хто керуючий
J104?» чи «скільки в нас магазинів?» відповідав реальними іменами, а не
вигадував. Без `ANTHROPIC_API_KEY` є два безкоштовні рівні нижче:
спершу пробує власну AI-модель Cloudflare (розуміє довільні питання),
а кілька найчастіших запитань саме такого типу («хто керуючий J104»,
«скільки магазинів», «хто сьогодні активний», «<Ім'я> активний?»)
додатково отримують реальну відповідь із бази навіть без жодного AI —
див. нижче. Поза цим бот не вигадує цифр і прямо каже, коли не знає.
На щось справді серйозне чи поза межами того,
що можна вирішити текстом (кадрове питання, конфлікт, рішення
керівника) — прямо радить звернутись до District Manager'а чи адміна
чату, а не вдає, що може це залагодити сам (аналог «передачі на
оператора» — тут немає окремої черги живих людей, тому це порада, а не
технічна передача діалогу).

**Класифікація наміру (Intent), без другого виклику API:** та сама
відповідь Claude повертається у структурованому вигляді (JSON-схема, яку
гарантує сам API — не просте прохання «поверни JSON» в тексті промпту,
яке модель могла б проігнорувати) — окрім самого тексту відповіді, у
кожній відповіді є `intent` (greeting/question_data/question_general/
complaint/human_request/feedback/media_comment/small_talk/
spam_or_irrelevant/unknown), `sentiment`, `urgency` і `requires_human`.
Якщо `requires_human: true` (кадрове питання, конфлікт, пряме прохання
покликати людину, чи роздратований тон разом із високою терміновістю) —
запис іде в лог (`/askbotescalations`, адміни чату) — ніхто не пінгується
в моменті, це список «чи було щось, що варто переглянути». `intent`/
`sentiment`/`urgency` кожної відповіді видно й у `/askbotfeedback`.

Зіставляється лише окреме слово «бот» —
«робота»/«робот» не рахуються. Без секрета працює й так —
просто замість відповіді від Claude бот бере одну із заздалегідь
написаних заготовок (коротка мотивація в тому самому стилі, що й решта
бота), без жодних витрат — медіа-аналіз без ключа, звісно, недоступний.
Ліміт — 20 AI-відповідей на годину на чат (захист від випадкового
або навмисного спаму запитами); понад ліміт бот теж відповідає, просто
заготовленою фразою замість виклику Claude.

**Завжди щось відповідає, навіть при збоях.** Раніше, якщо будь-який крок
всередині обробки звернення падав з помилкою (нетривке зникнення мережі
до Telegram чи Firestore), бот мовчав повністю — жодного повідомлення,
навіть заготовленого. Саме так і сталось одного разу в чаті "Менеджмент":
кілька звернень зі словом «бот» лишились узагалі без відповіді. Тепер
кожен ризикований крок (перевірка юзернейму бота, читання стану чату з
Firestore, довідка про магазини, сам виклик Claude, надсилання
повідомлення) обгорнутий у власний try/catch — будь-яка окрема відмова
деградує до заготовленої фрази замість повної тиші.

**Фідбек на AI-відповіді (безкоштовно):** поставте 👍/❤️/🔥/👏 (позитив)
чи 👎/💩/😡/🤡/😢 (негатив) реакцією на будь-яку AI-відповідь бота — це
записується в Firestore. `/askbotfeedback` (адміни чату) показує загальний
підсумок 👍/👎 і текст останніх відповідей, що отримали 👎 — щоб було що
конкретно переглянути й, за потреби, скоригувати системний промпт
(`ASK_BOT_SYSTEM_PROMPT` у `worker.js`). Заготовлені (без AI) відповіді
у фідбек не потрапляють — там нема чого покращувати, текст фіксований.

**Якщо ask-бот раз у раз відповідає лише заготовленою фразою** (без
реального контексту, ігнорує суть питання) — причину видно командою
`/askbotdebug` (адміни чату). Якщо причина "немає ключа
`ANTHROPIC_API_KEY`" — це НЕ помилка, а свідомий безкоштовний режим:
бот повністю розрахований на роботу без платного AI-виклику
(`ASK_BOT_FALLBACK_REPLIES` — саме для цього). Будь-яка інша причина
(мережева помилка, відмова від Anthropic API — неправильний ключ,
вичерпаний ліміт, недоступна модель, порожня чи пошкоджена відповідь)
означає, що ключ ЄСТЬ, але виклик чомусь не спрацював — і це вже варто
розглянути, з реальним текстом помилки, без потреби в доступі до логів
Cloudflare.

**Другий, теж повністю безкоштовний AI-рівень — Cloudflare Workers AI
(`askWorkersAI` у `worker.js`):** якщо `ANTHROPIC_API_KEY` не
налаштований (чи Claude з якоїсь причини не відповів), а питання
текстове (без фото/документа), бот пробує власну хмарну модель
Cloudflare (`@cf/google/gemma-4-26b-a4b-it` — Gemma 4, побудована на
дослідженнях Gemini 3, флагманська модель у поточному getting-started
гайді самого Cloudflare) через `[ai]` binding у `wrangler.toml` —
жодного окремого ключа, жодного облікового запису, крім самого
Cloudflare, який тут уже є. Це справжній AI, що розуміє довільні
запитання (не лише наперед прописані шаблони), просто слабший за
Claude. Безкоштовно в межах 10 000 Neurons/день на Workers
Free-плані (скидається щодня о 00:00 UTC, картка не потрібна — понад
ліміт запити просто не проходять, а не тарифікуються) — типова коротка
відповідь коштує приблизно 15-20 Neurons, тобто сотні безкоштовних
відповідей на день із запасом для реального навантаження цього бота.
На відміну від Claude, цей рівень не має структурованої класифікації
(`intent`/`sentiment`/`urgency`) чи рішення промовчати — завжди
відповідає, якщо його викликали.

**Третій рівень — предметні відповіді без жодного AI
(`matchFreeIntent` у `worker.js`):** якщо й Workers AI недоступний
(binding відсутній чи модель не відповіла), бот усе одно розпізнає
кілька найчастіших типів запитань і відповідає РЕАЛЬНИМИ даними з тієї
ж бази, а не текстом із набору заготовок:
- «Хто керуючий J104?» / «керуючий Погреби» — ім'я реального керуючого
  з довідника магазинів;
- «Хто керуючий у нас?» / «керуючий у нашому магазині?» — те саме, але
  без явного коду: бот бере власний прив'язаний магазин людини, яка
  запитує (`state.storeMembers`, встановлюється через `/mystore` або
  автоматично з надісланого звіту — той самий механізм, що й для
  вечірніх/фотозвітів);
- «Скільки у нас магазинів?» — реальна кількість і коди;
- «Хто сьогодні активний?» / «хто найактивніший?» — реальний топ
  активності (лише якщо в чаті прив'язана тема активності,
  `/setactivitytopic`);
- «Влад активний?» / «<Ім'я> активний сьогодні?» — чи саме ця людина
  проявляла активність сьогодні, з реальною кількістю балів. Ім'я
  зіставляється навіть якщо профіль у Telegram латиницею (той самий
  механізм транслітерації, що й для днів народження) — «Влад» знайде
  профіль «Vlad»;
- «Я сьогодні активний?» / «а мене сьогодні активний?» — те саме, але
  про саму людину, яка запитує, без потреби називати своє ім'я — бот
  бере її власний Telegram id.

Той самий контекст (власний магазин і власний id того, хто звертається
до бота) також потрапляє в підказку для Claude/Workers AI (рядок
«Звертається: Ім'я (магазин J104)» перед запитанням) — тож навіть коли
відповідає AI, а не ці шаблони, він знає, від чийого імені й з якого
магазину надійшло запитання, а не лише саме ім'я.

Якщо жоден рівень не спрацював (запитання не підпадає під жоден
шаблон, чи потрібних даних немає — наприклад, тема активності не
прив'язана) — бот чесно переходить до звичайної заготовленої фрази, а
не вигадує відповідь. Повний порядок: Claude (якщо є платний ключ) →
Cloudflare Workers AI (безкоштовний, довільні питання) → предметні
шаблони без AI (безкоштовно, кілька конкретних питань) → заготовлена
фраза.

## 4. Опублікувати нові Firestore-правила

Цей бот додає нову колекцію `telegram-bot` — правила для неї вже є в
`../firestore.rules`, лишилось опублікувати їх (одноразово, з кореня
репозиторію):

```bash
npx firebase-tools login
npx firebase-tools deploy --only firestore:rules
```

## 5. Додати бота в груповий чат

1. Додайте бота як учасника групового чату дістрикту.
2. Зробіть його **адміністратором** (потрібно для видалення/бану/муту та
   закріплення повідомлень) — права: Delete messages, Ban users, Pin
   messages.
3. Напишіть у чаті `/help` — бот покаже список команд.

## Керування через веб

Більшість налаштувань (правила чату, нагадування, вікна перевірки звітів,
дайджест, привітання, попередження, прив'язки учасників до магазинів) можна
міняти без Telegram-команд — прямо на дашборді (`../index.html`), вкладка
**🤖 Telegram-бот** (видима District Manager після входу). Прив'язку самих
тем форуму (`/setreportstopic`, `/setphotoreportstopic`, `/settaskstopic`) і
модерацію (ban/mute/warn) все одно виконують команди в Telegram.

## Що вміє бот

- **Адміністрування**: `/ban`, `/kick`, `/mute`, `/unmute`, `/warn` (3
  попередження → авто-мут на годину), `/pin`, `/del`, `/setrules`/`/rules`;
  антифлуд (>6 повідомлень за 10 сек → мут на 5 хв); welcome-повідомлення
  новим учасникам.
- **Аналіз активності**: `/stats` — топ активних учасників чату (сьогодні
  або за тиждень).
- **Дані дістрикту**: `/vacancies` — прострочені вакансії (>30 днів
  відкриті); `/activity` — керуючі, які не заходили на сайт >7 днів або
  жодного разу. Дані ті самі, що на вкладках «Вакансії» й «Активність»
  дашборду.
- **Нагадування**: `/addreminder 09:00 daily текст` (або
  `/addreminder 09:00 пн,ср,пт текст`) — свої нагадування в чаті;
  `/reminders`, `/delreminder <id>`.
- **Щоденний дайджест**: `/digest on 08:00` — щодня о вказаному часі бот
  сам надсилає `/vacancies` + `/activity` без запиту.
- **Приєднання до привітань** (безкоштовно, без зовнішніх API): коли хтось
  у чаті вітає колегу (день народження, підвищення, ювілей, перемога
  тощо), бот сам додає своє привітання у відповідь — визначає тип приводу
  за ключовими словами й бере відповідний варіант тексту з набору, а якщо
  в повідомленні є згадка людини — додає ім'я. Не повторює тему частіше
  ніж раз на 2 години в одній темі. Вимкнути — `/congrats off`.
- **Щоранкове привітання**: `/morning on 10:00`, написана в потрібній темі
  (або в General) — щодня о вказаному часі бот сам надсилає туди привітання
  й мотиваційне побажання на день (випадкове з набору текстів, щоб не
  повторювалось щодня). Вимкнути — `/morning off`.
- **Звіти магазинів у темі форуму**: прив'яжіть тему (напр. «Звіти/показники»)
  командою `/setreportstopic`, написаною **всередині цієї теми**. Бот
  розпізнає код магазину (напр. `J104`) будь-де в тексті повідомлень цієї
  теми, надісланих у вікні `17:00–23:00` (змінити: `/reportswindow ГГ:ХХ
  ГГ:ХХ`), плюс 15-хвилинний запас часу — звіт, надісланий буквально в
  останні хвилини, теж зарахується. Через 15 хв після кінця вікна сам
  напише в тему, які магазини не відзвітували; перевірити достроково —
  `/reportstatus`.
- **Щомісячний чекліст магазинів**: прив'яжіть тему (напр. «Завдання»)
  командою `/settaskstopic`, написаною **всередині цієї теми**. 1, 2 і 3
  числа о 12:00 бот сам надсилає туди чекліст (закриття таймплану, SALVY,
  касова/термінальна стрічка, касова документація) разом з опитуванням —
  кожен магазин обирає свій код, коли всі пункти виконано. Наступного дня
  опитування повторюється, але вже лише для тих, хто ще не відповів, із
  дружнім нагадуванням. Перевірити статус достроково — `/checkliststatus`.
- **Ранкові фотозвіти по мінусових залишках**: прив'яжіть тему командою
  `/setphotoreportstopic`, написаною **всередині цієї теми** — або нічого
  не робіть: якщо тема ще не прив'язана, а прийшло фото з підписом, що є
  точно кодом магазину (напр. "J104", без нічого зайвого), бот сам
  розпізнає й прив'яже цю тему автоматично. Магазин
  скидає туди фото — з кодом магазину в підписі, або й без підпису, якщо
  учасник прив'язаний до магазину (див. нижче). Вікно перевірки — типово
  `08:00–12:00` (змінити: `/photoreportswindow ГГ:ХХ ГГ:ХХ`), плюс
  15-хвилинний запас часу. Через 15 хв після кінця вікна бот сам нагадає
  магазинам, які не встигли, опрацювати мінусові залишки й прописати
  коментарі. Перевірити достроково — `/photoreportstatus`.
- **Стріки магазинів** (безкоштовно, автоматично): кожен магазин, що
  вчасно звітує (вечірній текстовий звіт і/або ранковий фотозвіт —
  рахуються окремо), накопичує стрік — «N днів поспіль без пропуску».
  Один пропуск обнуляє лічильник до 0. Дані й далі накопичуються (їх
  бачить ask-бот і `/streaks`), але в підсумковому повідомленні в кінці
  кожного вікна більше НЕ друкується — там тепер реальні показники
  дня (нижче), а не стріки; повний список стріків у будь-який момент —
  `/streaks`.
- **Реальні показники дня з вечірніх звітів** (безкоштовно, автоматично):
  бот читає не лише "хто відзвітував", а й САМІ ЦИФРИ з тексту звіту —
  Виторг, Покупці, Середня покупка та Енерджі (парсить розділ "Факт",
  тобто реальний результат, а не план; толерантно до того, як
  по-різному керуючі це пишуть — з емодзі чи без, з "грн" чи без,
  "117 509" чи "117509", "Енерджі" чи скорочено "Ен", ціле число чи з
  комою/крапкою для Енерджі — "8.9"). Якщо конкретне поле в тексті не
  знайдено (наприклад, замість цифри Енерджі хтось написав коментар) —
  це поле просто пропускається для цього магазину, а не вигадується. У
  підсумковому повідомленні в кінці вікна звітів (замість стріків)
  з'являється блок "📊 Показники дня" — який магазин сьогодні з
  найбільшим виторгом, найбільшою кількістю покупців, найбільшим
  середнім чеком і найвищим Енерджі. Звіт без жодних розпізнаваних
  цифр просто не потрапляє в підсумок.

  **Фото-звіти теж читаються** (безкоштовно, той самий Workers AI):
  якщо у тексті/підписі повідомлення немає розпізнаваних цифр, а
  фотографія є (скріншот каси/BI-системи чи навіть рукописний список) —
  бот показує це фото тій самій безкоштовній моделі й просить прочитати
  ті самі чотири показники з зображення (точний формат запиту з
  зображенням підтверджено безпосередньо зі схеми самої моделі —
  `{type: "image_url", image_url: {url: "data:..."}}`, стандартна для
  OpenAI-сумісних API). Якщо цифра на фото не видно — модель просто
  пропускає цей рядок, як і при звичайному текстовому звіті; нічого
  не вигадується. Відео-звіти поки не підключено — для них немає
  простого способу передати ключові кадри в модель, а розпізнавання
  мовлення (голосового супроводу) не було жодним із запитаних форматів.
- **Привітання з днем народження** (безкоштовно, автоматично): `/birthdays
  on [ГГ:ХХ]` (типово 08:00), написана в потрібній темі (або в General) —
  щодня о вказаному часі бот сам перевіряє список іменинників і, якщо
  сьогодні чийсь день народження, **першим** пише привітання в чат — з
  особистим підписом District Manager'а і закликом приєднатись у
  коментарях, а не лише додається до вже написаного кимось привітання (як
  «Приєднання до привітань» вище). Список днів народжень (ім'я, прізвище,
  день+місяць, магазин) зберігається в Firestore (`kyiv1/birthdays`, той
  самий проєкт, що й дашборд) і поки що редагується напряму там — без
  окремої команди для редагування списку. Вітає лише тих, кого впізнав
  серед реальних учасників чату (за іменем з профілю Telegram, включно зі
  скороченнями на кшталт «Марк А.» чи «М. Афонічев», і незалежно від того,
  кирилицею чи латиницею записане ім'я в Telegram-профілі — «Олег
  Гаценко» так само впізнається як «Oleh Hatsenko», за офіційною
  транслітерацією — а якщо однакове скорочення підходить одразу кільком
  людям, уточнює за магазином, використовуючи прив'язку з
  `/storepoll`/`/mystore`; якщо однозначно визначити не вдалось —
  привітання не надсилається, щоб не помилитись) і
  хто досі **в групі** — якщо людини немає в чаті або вона з нього
  вийшла/видалена, привітання теж не надсилається. Вимкнути —
  `/birthdays off`.
- **Прив'язка учасника до магазину**: відбувається **автоматично** — щойно
  хтось один раз напише однозначний код магазину в темі звітів, бот сам
  запам'ятовує цю людину за цим магазином назавжди (в межах чату), і всі
  наступні її повідомлення/фото зараховуються навіть без коду в тексті.
  Ручне керування також є: `/mystore J104` — прив'язати себе самому;
  `/linkstore J104` (відповіддю на повідомлення) — адмін прив'язує когось
  іншого; `/storemembers` — список прив'язок; `/storepoll` (адміни чату) —
  надіслати всім опитування «оберіть свій магазин» одним натисканням
  (нативний Telegram-поллінг, не анонімний, щоб зарахувати відповідь саме
  тому, хто натиснув) — з поясненням у тексті, що це потрібно для
  подальшої комунікації; надсилається в тему «Активності», якщо вона
  прив'язана (`/setactivitytopic`), інакше — туди, звідки викликали
  команду.
- **Довідник магазинів дистрикту**: `/stores` — список усіх магазинів з
  керуючими (та сама реальна база, що вже показує дашборд і на яку
  відповідає ask-бот через `matchFreeIntent`), доступно всім, не лише
  адмінам.
- **Швидке меню кнопками** (безкоштовно): `/menu` — надсилає повідомлення з
  кнопками (Telegram inline keyboard) замість команд для набору: 🏆
  Рейтинг, 🔥 Стріки, 🏪 Мій магазин, ❓ Довідка, 🏬 Магазини дистрикту.
  Кожна кнопка викликає ту саму логіку, що й відповідна команда —
  жодного дубльованого коду. Потребує кроку 3 в налаштуванні
  (`callback_query` в `allowed_updates`,
  див. вище) — без нього кнопки видно, але натискання нічого не робить.
- **Рівні та рейтинг** (безкоштовно, без зовнішніх сервісів): за активність
  у чаті нараховуються бали — повідомлення, фото/відео/документи, згадки
  про виконані завдання чи результати, підтримка колег, і більші бонуси за
  перший вечірній звіт, ранковий фотозвіт мінусових залишків чи
  підтвердження щомісячного чекліста (по кожному магазину — раз на день).
  Бали складаються в рівні (від «Новачок» до «Легенда дістрикту»).
  `/rating` (або `/top`) — топ-10 прямо в чаті; повний лідерборд з рівнями
  — на дашборді, вкладка **🤖 Telegram-бот → Рейтинг**. Цей рейтинг і рівні
  накопичуються назавжди, без скидання.
- **Щоденна статистика активності в темі форуму**: прив'яжіть тему (напр.
  «Активності/Акції») командою `/setactivitytopic`, написаною **всередині
  цієї теми**. О 10:00 бот сам надсилає туди підсумок активності **за
  вчора**, о 17:00 — зріз **за сьогодні** (з рівнями й короткою
  мотиваційною фразою) — цей рахунок щодня оновлюється з нуля. Загальний
  рейтинг і рівні (`/rating`, сайт) — окремий, накопичувальний лічильник,
  який ця щоденна статистика жодним чином не зачіпає.
- **Дайджест досягнень за тиждень** (у ту саму тему): щопонеділка о 10:01
  бот сам підбиває підсумки минулого тижня (пн–нд) — найактивніші
  учасники за балами, магазини з найбільшою кількістю виконаних завдань
  (вечірні звіти + ранкові фотозвіти), і — якщо ввімкнено крок «Реакції»
  вище — чиє привітання за тиждень зібрало найбільше реакцій 👍❤️.
  Завершується короткою мотиваційною фразою.
- **Тригери на реакції** (безкоштовно, без зовнішніх сервісів): бот реагує
  не лише на текст, а й на емодзі-реакції під повідомленнями. `/trackack
  <мітка>`, написана **відповіддю на повідомлення** (напр. інструкцію чи
  оголошення), позначає його для відстеження — відтоді будь-яка реакція
  від учасника чату зараховується як «ознайомлений(а)» в базі бота.
  `/ackstatus` (відповіддю на позначене повідомлення) — хто вже
  ознайомився і хто з відомих боту учасників чату ще ні; `/acklist` —
  список усіх позначених повідомлень у чаті. Потребує кроку «Реакції»
  вище (тип `message_reaction`) — без нього команди працюють, але
  реакції не зараховуються. Це загальний механізм — той самий принцип
  (реакція → подія в базі) бот може використовувати і для інших
  сценаріїв за потреби, не лише для ознайомлення з інструкціями.

Повний список команд у самому боті: `/help`.

## Обмеження безкоштовних планів

- Firestore Spark: 50 000 читань / 20 000 записів на день — для одного-двох
  групових чатів дістрикту величезний запас.
- Cloudflare Workers Free: 100 000 запитів/день — вебхук + cron кожні 5 хв
  (≈288 запусків/день) укладаються з великим запасом.
- Нагадування спрацьовують із точністю до 5 хв (крок cron-тригера); час у
  `/addreminder` й `/digest` автоматично округлюється до найближчих 5 хв.

## Локальна перевірка

```bash
wrangler dev
```

Відкриє локальний URL — можна тимчасово прив'язати webhook до нього через
`ngrok`/`cloudflared tunnel`, якщо треба дебажити зміни перед деплоєм.
