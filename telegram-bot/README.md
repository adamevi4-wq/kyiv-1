# Telegram-бот Kyiv-1

Бот для групового чату дістрикту: адміністрування (модерація, попередження,
антифлуд, welcome-повідомлення), статистика активності учасників, звіти по
вакансіях/активності керуючих з дашборду (`../index.html`) та запрограмовані
нагадування й щоденний дайджест.

Працює через Telegram webhook на **Cloudflare Workers** (безкоштовно, без
власного сервера) і зберігає свій стан у тому самому безкоштовному Firebase-
проєкті (`district-tracker-ef4c6`), що й дашборд — колекція `telegram-bot`.
Cron-тригер Cloudflare (раз на 5 хв) розсилає нагадування та дайджест.

## 1. Створити бота в Telegram

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot`, дайте назву.
2. Отримаєте **токен** виду `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — знадобиться нижче.
3. (Бажано) `/setprivacy` → `Disable` — щоб бот бачив усі повідомлення в
   групі, а не лише команди, адресовані йому (потрібно для антифлуду й
   статистики).

## 2. Розгорнути Worker на Cloudflare

Потрібен безкоштовний акаунт на [cloudflare.com](https://dash.cloudflare.com/sign-up).

```bash
cd telegram-bot
npm install -g wrangler   # якщо ще не встановлено
wrangler login

wrangler secret put BOT_TOKEN
# вставте токен від BotFather

wrangler secret put WEBHOOK_SECRET
# вставте будь-який випадковий рядок (напр. відкрийте
# https://www.uuidgenerator.net і скопіюйте один UUID) — це пароль,
# яким Telegram підписуватиме запити до вашого Worker

wrangler deploy
```

Після `wrangler deploy` у терміналі з'явиться URL виду
`https://kyiv1-telegram-bot.<ваш-субдомен>.workers.dev` — він знадобиться
на наступному кроці.

### Автодеплой при кожній зміні коду (одноразове налаштування)

Це потрібно зробити лише один раз, руками, в самому Cloudflare — жоден
асистент не може увійти у ваш акаунт замість вас. Після цього кроку
`telegram-bot/worker.js` деплоїться сам при кожному push у `main`
(workflow [`deploy-telegram-bot.yml`](../.github/workflows/deploy-telegram-bot.yml)),
точно як `index.html` вже деплоїться на GitHub Pages — команда
`wrangler deploy` вище більше не знадобиться для звичайних оновлень коду
бота.

1. [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)
   → **Create Token** → шаблон **"Edit Cloudflare Workers"** → Create
   Token. Скопіюйте токен (показується один раз).
2. У Cloudflare Dashboard → **Workers & Pages** — у правій колонці є
   **Account ID**, скопіюйте і його.
3. У GitHub-репозиторії: **Settings → Secrets and variables → Actions →
   New repository secret** — додайте два секрети:
   - `CLOUDFLARE_API_TOKEN` — токен з кроку 1
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID з кроку 2

Після цього наступний push, що зачіпає `telegram-bot/`, задеплоїть Worker
автоматично; перший запуск можна ініціювати вручну — вкладка **Actions**
цього репозиторію → **Deploy Telegram bot (Cloudflare Worker)** → **Run
workflow**.

## 3. Підключити webhook

Один раз відкрийте в браузері (підставте свій `BOT_TOKEN`, `WORKER_URL` і
`WEBHOOK_SECRET`):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WORKER_URL>&secret_token=<WEBHOOK_SECRET>
```

Успішна відповідь: `{"ok":true,"result":true,...}`.

### Реакції (для щотижневого дайджесту й відстеження ознайомлень, опційно)

Без цього кроку все інше в боті працює нормально — не пропускайте
попередній крок, а цей робіть лише якщо хочете, щоб:
- щотижневий дайджест показував, чиє привітання зібрало найбільше
  реакцій 👍❤️🔥 (потрібен тип `message_reaction_count`);
- і/або запрацювали «Тригери на реакції» (`/trackack` — ознайомлення з
  інструкціями через реакції; потрібен тип `message_reaction`).

За замовчуванням Telegram не надсилає боту жодних даних про реакції —
треба один раз переустановити webhook, вказавши явно, які типи оновлень
бот хоче отримувати (це замінює список типів повністю, тож перелічіть
усі, а не лише нові):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WORKER_URL>&secret_token=<WEBHOOK_SECRET>&allowed_updates=["message","poll","poll_answer","message_reaction","message_reaction_count"]
```

Успішна відповідь та сама: `{"ok":true,"result":true,...}`. Якщо цей крок
пропустити — весь інший функціонал працює як завжди, просто рядок
"найпопулярніше привітання тижня" в щотижневому дайджесті не з'явиться,
а реакції на повідомлення під `/trackack` не зараховуватимуться (сама
команда й `/ackstatus`/`/acklist` працюють одразу, незалежно від цього
кроку — просто список «ознайомились» лишиться порожнім).

## 4. Опублікувати нові Firestore-правила

Цей бот додає нову колекцію `telegram-bot` — правила для неї вже є в
`../firestore.rules`, лишилось опублікувати їх (одноразово, з кореня
репозиторію):

```bash
npx firebase-tools login
npx firebase-tools deploy --only firestore:rules
```

## 5. Додати бота в груповий чат

1. Додайте бота як учасника групового чату дістрикту.
2. Зробіть його **адміністратором** (потрібно для видалення/бану/муту та
   закріплення повідомлень) — права: Delete messages, Ban users, Pin
   messages.
3. Напишіть у чаті `/help` — бот покаже список команд.

## Керування через веб

Більшість налаштувань (правила чату, нагадування, вікна перевірки звітів,
дайджест, привітання, попередження, прив'язки учасників до магазинів) можна
міняти без Telegram-команд — прямо на дашборді (`../index.html`), вкладка
**🤖 Telegram-бот** (видима District Manager після входу). Прив'язку самих
тем форуму (`/setreportstopic`, `/setphotoreportstopic`, `/settaskstopic`) і
модерацію (ban/mute/warn) все одно виконують команди в Telegram.

## Що вміє бот

- **Адміністрування**: `/ban`, `/kick`, `/mute`, `/unmute`, `/warn` (3
  попередження → авто-мут на годину), `/pin`, `/del`, `/setrules`/`/rules`;
  антифлуд (>6 повідомлень за 10 сек → мут на 5 хв); welcome-повідомлення
  новим учасникам.
- **Аналіз активності**: `/stats` — топ активних учасників чату (сьогодні
  або за тиждень).
- **Дані дістрикту**: `/vacancies` — прострочені вакансії (>30 днів
  відкриті); `/activity` — керуючі, які не заходили на сайт >7 днів або
  жодного разу. Дані ті самі, що на вкладках «Вакансії» й «Активність»
  дашборду.
- **Нагадування**: `/addreminder 09:00 daily текст` (або
  `/addreminder 09:00 пн,ср,пт текст`) — свої нагадування в чаті;
  `/reminders`, `/delreminder <id>`.
- **Щоденний дайджест**: `/digest on 08:00` — щодня о вказаному часі бот
  сам надсилає `/vacancies` + `/activity` без запиту.
- **Приєднання до привітань** (безкоштовно, без зовнішніх API): коли хтось
  у чаті вітає колегу (день народження, підвищення, ювілей, перемога
  тощо), бот сам додає своє привітання у відповідь — визначає тип приводу
  за ключовими словами й бере відповідний варіант тексту з набору, а якщо
  в повідомленні є згадка людини — додає ім'я. Не повторює тему частіше
  ніж раз на 2 години в одній темі. Вимкнути — `/congrats off`.
- **Щоранкове привітання**: `/morning on 10:00`, написана в потрібній темі
  (або в General) — щодня о вказаному часі бот сам надсилає туди привітання
  й мотиваційне побажання на день (випадкове з набору текстів, щоб не
  повторювалось щодня). Вимкнути — `/morning off`.
- **Звіти магазинів у темі форуму**: прив'яжіть тему (напр. «Звіти/показники»)
  командою `/setreportstopic`, написаною **всередині цієї теми**. Бот
  розпізнає код магазину (напр. `J104`) будь-де в тексті повідомлень цієї
  теми, надісланих у вікні `17:00–23:00` (змінити: `/reportswindow ГГ:ХХ
  ГГ:ХХ`), плюс 15-хвилинний запас часу — звіт, надісланий буквально в
  останні хвилини, теж зарахується. Через 15 хв після кінця вікна сам
  напише в тему, які магазини не відзвітували; перевірити достроково —
  `/reportstatus`.
- **Щомісячний чекліст магазинів**: прив'яжіть тему (напр. «Завдання»)
  командою `/settaskstopic`, написаною **всередині цієї теми**. 1, 2 і 3
  числа о 12:00 бот сам надсилає туди чекліст (закриття таймплану, SALVY,
  касова/термінальна стрічка, касова документація) разом з опитуванням —
  кожен магазин обирає свій код, коли всі пункти виконано. Наступного дня
  опитування повторюється, але вже лише для тих, хто ще не відповів, із
  дружнім нагадуванням. Перевірити статус достроково — `/checkliststatus`.
- **Ранкові фотозвіти по мінусових залишках**: прив'яжіть тему командою
  `/setphotoreportstopic`, написаною **всередині цієї теми** — або нічого
  не робіть: якщо тема ще не прив'язана, а прийшло фото з підписом, що є
  точно кодом магазину (напр. "J104", без нічого зайвого), бот сам
  розпізнає й прив'яже цю тему автоматично. Магазин
  скидає туди фото — з кодом магазину в підписі, або й без підпису, якщо
  учасник прив'язаний до магазину (див. нижче). Вікно перевірки — типово
  `08:00–12:00` (змінити: `/photoreportswindow ГГ:ХХ ГГ:ХХ`), плюс
  15-хвилинний запас часу. Через 15 хв після кінця вікна бот сам нагадає
  магазинам, які не встигли, опрацювати мінусові залишки й прописати
  коментарі. Перевірити достроково — `/photoreportstatus`.
- **Прив'язка учасника до магазину**: відбувається **автоматично** — щойно
  хтось один раз напише однозначний код магазину в темі звітів, бот сам
  запам'ятовує цю людину за цим магазином назавжди (в межах чату), і всі
  наступні її повідомлення/фото зараховуються навіть без коду в тексті.
  Ручне керування також є: `/mystore J104` — прив'язати себе самому;
  `/linkstore J104` (відповіддю на повідомлення) — адмін прив'язує когось
  іншого; `/storemembers` — список прив'язок.
- **Рівні та рейтинг** (безкоштовно, без зовнішніх сервісів): за активність
  у чаті нараховуються бали — повідомлення, фото/відео/документи, згадки
  про виконані завдання чи результати, підтримка колег, і більші бонуси за
  перший вечірній звіт, ранковий фотозвіт мінусових залишків чи
  підтвердження щомісячного чекліста (по кожному магазину — раз на день).
  Бали складаються в рівні (від «Новачок» до «Легенда дістрикту»).
  `/rating` (або `/top`) — топ-10 прямо в чаті; повний лідерборд з рівнями
  — на дашборді, вкладка **🤖 Telegram-бот → Рейтинг**. Цей рейтинг і рівні
  накопичуються назавжди, без скидання.
- **Щоденна статистика активності в темі форуму**: прив'яжіть тему (напр.
  «Активності/Акції») командою `/setactivitytopic`, написаною **всередині
  цієї теми**. О 10:00 бот сам надсилає туди підсумок активності **за
  вчора**, о 17:00 — зріз **за сьогодні** (з рівнями й короткою
  мотиваційною фразою) — цей рахунок щодня оновлюється з нуля. Загальний
  рейтинг і рівні (`/rating`, сайт) — окремий, накопичувальний лічильник,
  який ця щоденна статистика жодним чином не зачіпає.
- **Дайджест досягнень за тиждень** (у ту саму тему): щопонеділка о 10:01
  бот сам підбиває підсумки минулого тижня (пн–нд) — найактивніші
  учасники за балами, магазини з найбільшою кількістю виконаних завдань
  (вечірні звіти + ранкові фотозвіти), і — якщо ввімкнено крок «Реакції»
  вище — чиє привітання за тиждень зібрало найбільше реакцій 👍❤️.
  Завершується короткою мотиваційною фразою.
- **Тригери на реакції** (безкоштовно, без зовнішніх сервісів): бот реагує
  не лише на текст, а й на емодзі-реакції під повідомленнями. `/trackack
  <мітка>`, написана **відповіддю на повідомлення** (напр. інструкцію чи
  оголошення), позначає його для відстеження — відтоді будь-яка реакція
  від учасника чату зараховується як «ознайомлений(а)» в базі бота.
  `/ackstatus` (відповіддю на позначене повідомлення) — хто вже
  ознайомився і хто з відомих боту учасників чату ще ні; `/acklist` —
  список усіх позначених повідомлень у чаті. Потребує кроку «Реакції»
  вище (тип `message_reaction`) — без нього команди працюють, але
  реакції не зараховуються. Це загальний механізм — той самий принцип
  (реакція → подія в базі) бот може використовувати і для інших
  сценаріїв за потреби, не лише для ознайомлення з інструкціями.

Повний список команд у самому боті: `/help`.

## Обмеження безкоштовних планів

- Firestore Spark: 50 000 читань / 20 000 записів на день — для одного-двох
  групових чатів дістрикту величезний запас.
- Cloudflare Workers Free: 100 000 запитів/день — вебхук + cron кожні 5 хв
  (≈288 запусків/день) укладаються з великим запасом.
- Нагадування спрацьовують із точністю до 5 хв (крок cron-тригера); час у
  `/addreminder` й `/digest` автоматично округлюється до найближчих 5 хв.

## Локальна перевірка

```bash
wrangler dev
```

Відкриє локальний URL — можна тимчасово прив'язати webhook до нього через
`ngrok`/`cloudflared tunnel`, якщо треба дебажити зміни перед деплоєм.
